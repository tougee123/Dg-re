## 纠正和新增事实

| 原字节位置 | 可确认的局部事实 | 不可外推的结论 |
|---|---|---|
| `0x1003A99EC`，间接调用 `0x1003A9A00` | 先将候选对象保存到 frame+0x18，再调用导入槽 `0x100B942C8`；该槽的导入名是 `_objc_retain`，不是 `_objc_retainAutorelease` | 导入名不是运行时实现/写集或寿命证明 |
| `0x1003A9A04` | 调用后从当次 frame+0x18 和 frame+0xC8 重新读值并写槽，不使用返回寄存器 x0 作为该次写入值 | 不能假设外部调用前后保存槽和目标地址不变 |
| `0x100850BEC`、`0x100845FD4` | 保存候选 handle/object，再准备 x0=handle、w1=10001、x2=object，止于 `0x100845FE0` 调用 | 两个非连续窗口的测试是显式拼接前置状态，不证明中间 CFG 或真实 option 路由 |
| `0x100834BE0` | 先把 frame+0x1158 的值写到 frame+0x1160 指向地址，再读 handle；后续准备回调地址 `0x1003A8B1C` 和选项 20011 | 写目标与 handle 槽别名时，后读值改变；不能跳过地址别名条件 |
| `0x1008C7044`、`0x1008C7078` | 分别写 handle+0x240、handle+0x2B0；先推进参数游标，再读旧游标指向值 | 只核对局部表项/窗口，未证明所有参数选择和分支；游标槽别名有反例 |
| `0x1008C19AC`、`0x1008C19D4` | 两处调用前 x3 分别来自 handle+0x240、handle+0x250；其余参数为 x0=x20、x1=1、x2=x24 | 两处 context 不能合并；调用效果和真实端点身份未绑定 |
| `0x1008C2534`、`0x1008C2120` | 存在保存、替换及恢复 callback/context 的局部指令；替换 context 为包装上下文 x19，callback 为 `0x1008D4CB8` | 登记时 context 不一定等于调用时响应对象；未证明具体事务经过该包装路径或包装函数仅转发 |
| `0x10084968C`、`0x1005D0888` | JSON 调用前 data 来自当次 frame+0x1160 / frame+0x3768 指向槽，options=1、error=NULL；选择子为 `JSONObjectWithData:options:error:` | 未执行消息调用，不提供解析返回值；活跃 IMP、类和对象内容仍需绑定 |
| `0x10037C850` | 共享解析跳板从 FP 相对槽装载 x0..x4/IMP，经 `0x10037C868` 调用后保存 x0 | 不是 recharged 专用入口，不能凭此位置为实机响应指定端点 |

`parser-slot-writers.json` 另记录两个原始调用窗口：`0x100843FB0` 准备 x0=[frame+0x1160]、x1=0 后调用 `_objc_storeStrong`；`0x100849B48` 准备相同目标来源、x1=[frame+0x370] 后调用同一导入桩。这里只确认调用参数，未执行清空/替换、未证明其实际先后或某事务走到这些位置。因此“相同 frame+0x1160”不是登记对象和解析对象相同的证明。

## 本轮反例覆盖

负测覆盖：导入名/选择子/原字节/局部表项变异；外部调用后保存槽和目标地址改变；写后读别名；游标先写后读；primary/secondary context 不同；包装替换与恢复；解析时对象版本改变；遇到未知指令或 BL/BLR 必须停止。它们反驳不成立的静态简化，不代表原程序实际发生并发写入或任一合成状态可达。

执行器只支持明确列出的指令子集，不能执行完整回调。分支、共享跳板和完整回调 CFG 的原字节记录不等于已执行；非连续切片也不自动产生因果边。测试通过数量不换算为整体完成百分比。

## 面向新 App 的剩余 P0

|---|---|---|
| 1 / logind0 | 2456 字节最终正文构造；回调登记和 `0x1008496AC` 解析参数局部 | 将同一 frame/handle/事务的登记、包装还原、累积对象、当前解析数据版本联立；覆盖 frame+0x1160 的候选写者；构造记录不能当实际发送 |

| 2 / 百度前置请求 | completion 捕获槽、局部分派和消费来源 | 正常/错误/取消分别到真实授权请求的参数及状态依赖；只有副作用与完成行为等价后才能判断省略，不先删除也不宣称必需 |
| 3 / 启动与持久化 | 黑屏、历史合法激活后退出/重启进 UI；局部 ct 产出和比较 | 完整 sign/udid/endtime 的同次接受及拒绝条件、缓存准确格式/读回/回退、24B014 异步续执行到 UI；客户端兼容不等于可签发旧码的后端 |

本轮新增“可归属端点的实机最终响应”=0，“完整响应解码闭合”=0。历史成功观察不被否定，但还不能交付可上线的旧协议兼容 SDK。下一工作单从 logind0 的当前解析输入反向追到累积对象，优先打通一条完整响应链，再迁移到另两接口；不再扩大无目标的日志扫描或对象寿命穷举。
